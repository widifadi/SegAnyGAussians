================================================================================

    pip install "numpy<2" "opencv-python<4.12"

This installs:
- NumPy 1.26.x (latest 1.x, compatible with PyTorch 2.0.1)
- opencv-python 4.10.x (compatible with NumPy 1.x)

Verify:
    python -c "import numpy, cv2; print('NumPy:', numpy.__version__); print('OpenCV:', cv2.__version__)"

Expected:
    NumPy: 1.26.4
    OpenCV: 4.10.0.84

Why this is needed:
- PyTorch 2.0.1 (April 2023) was released BEFORE NumPy 2.0 (June 2024)
- PyTorch binaries were compiled against NumPy 1.x C API
- Using NumPy 2.x causes: RuntimeError: Numpy is not available
- opencv-python 4.12+ requires NumPy 2.x, so we pin to 4.10.x

11. WINDOWS-SPECIFIC FIX FOR SIMPLE-KNN (CRITICAL!)
================================================================================

IMPORTANT: Before installing CUDA extensions, you must fix simple-knn for Windows.
This solves the "DLL load failed" and "ModuleNotFoundError: No module named 'simple_knn._C'" errors.

STEP 11a: MODIFY SETUP.PY (REQUIRED)
--------------------------------------

Location: submodules\simple-knn\setup.py

Replace the entire content with:

---START OF FILE---
from setuptools import setup
from torch.utils.cpp_extension import CUDAExtension, BuildExtension
import os
import sys

cxx_compiler_flags = []
nvcc_compiler_flags = []

if os.name == 'nt':
    cxx_compiler_flags.append("/wd4624")

if sys.platform == "win32":
    nvcc_compiler_flags += [
        "-DWIN32_LEAN_AND_MEAN",
        "-allow-unsupported-compiler",
    ]

setup(
    name="simple_knn",
    packages=['simple_knn'],
    ext_modules=[
        CUDAExtension(
            name="simple_knn._C",
            sources=[
                "spatial.cu",
                "simple_knn.cu",
                "ext.cpp"
            ],
            extra_compile_args={"nvcc": nvcc_compiler_flags, "cxx": cxx_compiler_flags})
    ],
    cmdclass={
        'build_ext': BuildExtension.with_options(use_ninja=True)
    }
)
---END OF FILE---

Key change:
- Added packages=['simple_knn'] parameter (tells setuptools to include __init__.py)

Use any text editor:
    notepad submodules\simple-knn\setup.py

Or VS Code:
    code submodules\simple-knn\setup.py


STEP 11b: CREATE __INIT__.PY (REQUIRED)
-----------------------------------------

Location: submodules\simple-knn\simple_knn\__init__.py

Create this file with the following content:

---START OF FILE---
import os
import sys

# Add torch DLL directory to search path (Windows only)
try:
    import torch
    torch_lib_dir = os.path.join(os.path.dirname(torch.__file__), 'lib')
    if sys.platform == 'win32' and os.path.exists(torch_lib_dir):
        os.add_dll_directory(torch_lib_dir)
except Exception:
    pass

from simple_knn._C import *
---END OF FILE---

Reason: On Windows, Python needs the torch\lib directory in its DLL search
path to find c10.dll, torch_cpu.dll, and other PyTorch dependencies required
by the simple-knn CUDA extension.

Use any text editor to create this file:
    notepad submodules\simple-knn\simple_knn\__init__.py

Or use VS Code:
    code submodules\simple-knn\simple_knn\__init__.py

Copy and paste the content above, then save the file.

--------------------------------------------------------------------------------
A.1 WHY A DIFFERENT STACK IS NEEDED
--------------------------------------------------------------------------------

RTX 50 series (Blackwell) GPUs have compute capability 12.0 (sm_120).

- CUDA 11.8: does not support Blackwell at all
- PyTorch 2.6.x and below: sm_90 (Ada Lovelace) is the highest supported arch
  Running SAGA on these versions gives:
    RuntimeError: CUDA error: no kernel image is available for execution on the device
- PyTorch 2.9.1+cu128 on Windows: compiled_autograd.h causes C2872 MSVC error
  when building CUDA extensions (known incompatibility with MSVC 14.44)
- PyTorch 2.8.0+cu128: supports sm_120 AND compiles cleanly on Windows MSVC

A.7 PATCH THE THREE RASTERIZATION SETUP.PY FILES (REQUIRED FOR WINDOWS)
--------------------------------------------------------------------------------

Each of the three rasterization submodules needs Windows-specific nvcc flags.
Add `import sys` and the Windows block to their setup.py files.

The patched setup.py content (same pattern for all three — only `name` differs):

---START OF FILE---
from setuptools import setup
from torch.utils.cpp_extension import CUDAExtension, BuildExtension
import os
import sys
os.path.dirname(os.path.abspath(__file__))

nvcc_flags = ["-I" + os.path.join(os.path.dirname(os.path.abspath(__file__)), "third_party/glm/")]
if sys.platform == "win32":
    nvcc_flags += ["-DWIN32_LEAN_AND_MEAN", "-allow-unsupported-compiler"]

setup(
    name="diff_gaussian_rasterization",          # change per submodule
    packages=['diff_gaussian_rasterization'],     # change per submodule
    ext_modules=[
        CUDAExtension(
            name="diff_gaussian_rasterization._C", # change per submodule
            sources=[
            "cuda_rasterizer/rasterizer_impl.cu",
            "cuda_rasterizer/forward.cu",
            "cuda_rasterizer/backward.cu",
            "rasterize_points.cu",
            "ext.cpp"],
            extra_compile_args={"nvcc": nvcc_flags})
        ],
    cmdclass={
        'build_ext': BuildExtension
    }
)
---END OF FILE---

Apply to all three submodules:
  submodules\diff-gaussian-rasterization\setup.py

A.13 KNOWN ISSUES AND NOTES
--------------------------------------------------------------------------------

1. PyTorch 2.9.1+cu128 C2872 MSVC error:
   PyTorch 2.9.1's compiled_autograd.h(1134) uses ::std::is_same_v inside a
   template instantiation that MSVC 14.44 cannot resolve during CUDA cudafe
   host compilation. The -DWIN32_LEAN_AND_MEAN flag does NOT fix this.
   Solution: Use PyTorch 2.8.0+cu128 instead.

2. PyTorch 2.6.0+cu126 sm_120 error:
   "no kernel image is available for execution on the device" at runtime.
   PyTorch 2.6.x supports only up to sm_90. Upgrade to 2.8.0+cu128.

3. TORCH_CUDA_ARCH_LIST must include 12.0+PTX:
   The +PTX suffix enables PTX JIT fallback for forward compatibility.
   Without it, CUDA extensions built for sm_120 may not JIT-compile on
   future Blackwell sub-variants.

4. Do not use conda CUDA with this stack:
   Mixing conda CUDA 11.8 with system CUDA 12.8 and PyTorch 2.8.0+cu128
   causes version mismatches. Let PyTorch use the system CUDA directly.
